# Contributing with an agent

These instructions apply to maintaining this DAS repository checkout. They are not policy for a product that installs DAS. Installed skills use their own `SKILL.md` and supporting resources; keep repository contributor instructions outside their folders.

Read [CONTRIBUTING](CONTRIBUTING.md) for editable sources, checks and contribution handling, and the relevant [client guide](INSTALL.md) before changing installation behavior. If this edition contains `TARGET.json`, follow its source-preservation boundary in CONTRIBUTING.

- Keep each change tied to a concrete user outcome. For instruction changes, state the expected behavior and a task that would reveal its absence.
- Edit the owning sources identified in CONTRIBUTING. Regenerate supporting copies with the documented maintenance commands instead of editing generated files independently.
- Preserve unrelated work and product files. Keep private source material, credentials and customer information out of issues, examples and commits.
- Run the applicable offline checks. Report what was checked and any remaining limits; package integrity does not establish design quality or support for an untested client route.
- Keep raw model outputs unchanged when using them as evidence. A failing design result is not repaired by rewriting its evaluation criteria.
- Remove task-created disposable scratch before completion and retain useful outputs. Follow the contribution path in CONTRIBUTING; building a package does not publish a release.
